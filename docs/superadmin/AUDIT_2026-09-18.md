## Hallazgos de seguridad

1. La autorización administrativa nueva usa exclusivamente `app_metadata.platform_role`, perfil activo, permiso y alcance territorial; nunca `user_metadata`.
2. La función Edge exige AAL2. Se agregó el enrolamiento TOTP a la pantalla de acceso para la primera sesión administrativa.
3. La protección de contraseñas filtradas continúa desactivada y debe habilitarse en Auth antes de aprobar producción.
4. Los avisos `RLS enabled, no policy` de `admin_vault` y tablas Pulso son intencionales: son deny-by-default, con grants revocados y acceso mediante RPCs auditadas.
5. El único `SECURITY DEFINER` autenticado nuevo señalado por el advisor es `radar_authorized_pulse_v1`; su ejecución es intencional y valida primero el contexto canónico de campaña/municipio.
6. Se cerró la ejecución RPC de `handle_new_user()` y se agregaron índices a todas las claves foráneas nuevas del control plane. Los avisos restantes pertenecen a tablas anteriores de Campaign/Data Vault y quedan fuera de este frente.

## Decisión de integración

La consola se integrará en este repositorio como un shell protegido propio bajo `/admin/*`, sin alterar el dashboard municipal. El Site anterior no se importará como fuente ni se conectará mediante estados copiados. El frontend administrativo consumirá una API administrativa de servidor que entregue agregados mínimos; las operaciones privilegiadas usarán Edge Functions y funciones SQL auditadas. Las migraciones se revisarán y aplicarán primero en una rama Supabase QA.
